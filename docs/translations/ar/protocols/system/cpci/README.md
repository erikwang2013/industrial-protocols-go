# SDK بروتوكول CompactPCI

ينفّذ `kernel.Protocol` للوصول إلى ناقل CompactPCI عبر sysfs في Linux.

## البروتوكول

- **الاسم**: `cpci`
- **الأنواع (Variants)**: `cpci`
- **المنفذ الافتراضي**: 0 (ناقل معرف بالذاكرة)
- **النقل**: sysfs `/sys/bus/pci/devices/<BDF>/config`

يستخدم CompactPCI (PICMG 2.0) نفس الواجهة الكهربائية والبرمجية
لـ PCI التقليدي. يمرر المرمّز البايتات الخام بين التطبيق
ومساحة إعداد PCI عبر sysfs.

## متطلبات النواة

يجب تحميل وحدات النواة التالية:

- `pcieport` -- برنامج تشغيل منفذ PCI Express (لأنظمة CPCIe الهجينة)
- `pci_sysfs` -- واجهة PCI عبر sysfs (مدمجة في معظم النوى)
- `cpci_hotplug` -- وحدة تحكم الإدخال/الإخراج الساخن لـ CompactPCI (اختياري، للاستبدال الساخن)

يجب أن يكون نظام الملفات sysfs مركبًا عند `/sys`. وهذا هو الافتراضي
في جميع توزيعات Linux الحديثة.

الصلاحيات المطلوبة:
- وصول الجذر أو `CAP_SYS_ADMIN` للوصول إلى مساحة الإعداد
- ملف الإعداد مملوك لـ root:root بوضع 0600

## برنامج التشغيل

```go
d, err := cpci.NewCPCIDriver("0000:02:00.0")
if err != nil {
    log.Fatal(err)
}
defer d.Close()

tr := d.Transport()
// Use tr.Read/tr.Write for raw CPCI config space access
```

## CompactPCI مقابل PCI

يستخدم CompactPCI تعداد ناقل PCI القياسي ومساحة الإعداد.
الاختلافات الرئيسية عن PCI المكتبي:

- **عامل الشكل 3U/6U**: ميكانيكا Eurocard بموصلات دبوس-ومقبس
- **ترقيم النواقل**: يحصل كل مقطع هيكل CPCI على رقم ناقل PCI خاص به
- **الاستبدال الساخن**: يستخدم الاستبدال الساخن PICMG 2.1 نموذج الإدخال الساخن القياسي لـ PCI
- **فتحة النظام**: الناقل 0، الجهاز 0 هو وحدة تحكم فتحة النظام

## تنسيق BDF

عنوان الناقل هو سلسلة BDF (الناقل:الجهاز.الوظيفة):
- `0000:02:00.0` -- المجال 0000، الناقل 02، الجهاز 00، الوظيفة 0
- `0000:02:08.0` -- المجال 0000، الناقل 02، الجهاز 08، الوظيفة 0
