# SDK протокола VME / VPX

Реализует `kernel.Protocol` для доступа к шинам VMEbus и VPX через procfs Linux.

## Протокол

- **Имя**: `vme`
- **Варианты**: `vme`
- **Порт по умолчанию**: 0 (шина с отображаемой в память адресацией)
- **Транспорт**: procfs `/proc/vme/<slot>`

Кодек прозрачно передаёт сырые байты между приложением и адресным
пространством VME. Чтения и записи идут напрямую в шину через интерфейс
procfs, предоставляемый драйвером ядра VME.

## Требования к ядру

Должен быть загружен следующий модуль ядра:

- `vme_tsi148` — драйвер VME-моста Tundra TSI148 (самый распространённый)
  - Также поддерживаются: `vme_ca91cx42` (Universe II), `vme_user`

Файловая система procfs должна быть смонтирована в `/proc`.

Требуемые права:
- Для открытия `/proc/vme/<slot>` на чтение-запись требуется доступ root
- Узлы устройств принадлежат root:root

## Драйвер

```go
d, err := vme.NewVMEDriver(0) // слот 0
if err != nil {
    log.Fatal(err)
}
defer d.Close()

tr := d.Transport()
// Используйте tr.Read/tr.Write для прямого доступа к шине VME
```

## Режимы адресации VME

Кодек прозрачно пропускает все байты модификаторов адреса и адреса.
Приложения должны добавлять информацию об адресации в начало полезной
нагрузки данных:

- **A16**: 16-битное короткое адресное пространство ввода/вывода
- **A24**: 24-битное стандартное адресное пространство
- **A32**: 32-битное расширенное адресное пространство

## Совместимость с VPX

Системы VPX (VITA 46), предоставляющие совместимый с VME интерфейс procfs,
могут использовать этот драйвер. Нумерация слотов та же.
