# SDK протокола CompactPCI

Реализует `kernel.Protocol` для доступа к шине CompactPCI через sysfs Linux.

## Протокол

- **Имя**: `cpci`
- **Варианты**: `cpci`
- **Порт по умолчанию**: 0 (шина с отображаемой в память адресацией)
- **Транспорт**: sysfs `/sys/bus/pci/devices/<BDF>/config`

CompactPCI (PICMG 2.0) использует те же электрический и программный
интерфейсы, что и обычный PCI. Кодек прозрачно передаёт сырые байты
между приложением и конфигурационным пространством PCI через sysfs.

## Требования к ядру

Должны быть загружены следующие модули ядра:

- `pcieport` — драйвер порта PCI Express (для гибридных систем CPCIe)
- `pci_sysfs` — интерфейс PCI в sysfs (встроен в большинство ядер)
- `cpci_hotplug` — контроллер горячей замены CompactPCI (опционально, для hot-swap)

Файловая система sysfs должна быть смонтирована в `/sys`. Это поведение
по умолчанию во всех современных дистрибутивах Linux.

Требуемые права:
- Доступ root или `CAP_SYS_ADMIN` для доступа к конфигурационному пространству
- Файл конфигурации принадлежит root:root с правами 0600

## Драйвер

```go
d, err := cpci.NewCPCIDriver("0000:02:00.0")
if err != nil {
    log.Fatal(err)
}
defer d.Close()

tr := d.Transport()
// Используйте tr.Read/tr.Write для прямого доступа к конфигурационному пространству CPCI
```

## CompactPCI и PCI

CompactPCI использует стандартную нумерацию шин PCI и конфигурационное пространство.
Ключевые отличия от настольного PCI:

- **Форм-фактор 3U/6U**: механика Eurocard с разъёмами «штырь-гнездо»
- **Нумерация шин**: каждый сегмент шасси CPCI получает собственный номер шины PCI
- **Горячая замена**: PICMG 2.1 использует стандартную модель hotplug PCI
- **Системный слот**: шина 0, устройство 0 — контроллер системного слота

## Формат BDF

Адрес шины — строка BDF (Bus:Device.Function):
- `0000:02:00.0` — домен 0000, шина 02, устройство 00, функция 0
- `0000:02:08.0` — домен 0000, шина 02, устройство 08, функция 0
